## 2026-09-08: 본문 흐름과 문체 재작성

코딩 예제 다음의 로봇 비유와 중복 정의 투어를 제거했다. 코드 출력과 실행·검증의 차이에서 agent 정의를 도출하고, 환경 경계와 MDP 표현으로 이어지도록 재배치했다. 각 절의 시작과 끝을 실행 → 기록 → 보상 → gradient → 경험 재사용 → PPO → GRPO → tensor loss → credit → distillation → 수집 → 지연 → 예산 → 평가의 논리로 연결했다.

## 2026-09-08: 용어·텐서·인용 연결 개정의 자체 검증

외부 심사 결과가 아니라 이번 편집의 자체 검증 기록이다. 환경과 입력의 경계, 실행 과정과 trajectory 기록, 종료와 수집 중단, group과 batch 단위를 명시했다. 그림 2가 그림 1의 전체 경로라는 잘못된 캡션을 바로잡고, 용어표에서도 rollout과 trajectory를 분리했다.

## 선별 기준

개념의 원 출처, 해당 주장에 대한 직접 근거, 비교 실험·분석의 유무, 검증 가능한 공개 범위, 다른 참고문헌과의 중복을 기준으로 검토했다. 학회 이름이나 회사 명성만으로 품질을 판정하지 않았다. 원문 확인과 관련 실험 검토를 수행했으나 코드 재현 실험이나 독립적인 결과 검증을 완료한 것은 아니다.

자료 전체가 나쁘다는 판정과 이 글의 근거로 부적절하다는 판정을 구분한다. 이번 정리는 후자를 중심으로 진행했다.

## 조건부 유지

**Search-R1**: PPO와 GRPO를 같은 검색 과제에 적용하고 retrieval-token masking의 역할을 분석하므로 교육적 연결 가치가 있다. 다만 검토한 v1은 소형 모델, Wikipedia 기반 검색, QA exact-match reward 중심이다. 일부 비교의 초기 모델 조건 차이와 제한된 실험 설정을 고려해 최고 알고리즘 선정의 근거로 쓰지 않는다. 원문의 `DeepSeek-R1 extension` 표현을 DeepSeek-R1 checkpoint를 그대로 fine-tune했다는 뜻으로 옮기지 않는다. 실제 사용 모델과 학습 설정을 기준으로 서술한다. [원문 §4–5](https://arxiv.org/html/2503.09516v1)

**Dr. GRPO**: 길이 및 그룹 표준편차 normalization이 최적화 가중치를 바꾼다는 분석에 한정해 유지한다. normalization 제거가 모든 Agent의 성능을 개선한다는 결론은 제외한다. [원문 §3](https://arxiv.org/html/2503.20783v1)

**Qwen3 / Qwen3-Coder-Next / GLM-5 / DeepSeek-V3.2**: 학습 파이프라인과 설계 선택의 공식 공개 근거로 유지한다. 모델 간 leaderboard 차이를 특정 RL 기법의 인과적 효과로 해석하지 않는다. 특히 Qwen의 distillation 비용 절감 수치를 모든 Agent에 적용하지 않으며, GLM-5의 §4.1 그룹 중심 보상 식을 완전한 정책 objective로 복사하지 않는다.

## 문체 비교와 적용

정보이론, ODE/PDE, representation-collapse의 한국어 도입과 설명 문단을 비교했다. 공통적으로 도입은 독자에게 설명하는 `합니다`체, 본문의 정의·전개는 `이다/한다`체, 데모 조작 안내는 `바꿔보세요/확인해보세요`체를 사용한다. ODE/PDE는 그림과 직접 조작을 안내하는 비중이 크고, representation-collapse는 예제에서 문제를 끌어내고 적용 범위를 구분하는 연결 문단의 비중이 크다.

이 글은 representation-collapse의 연결된 설명을 기본으로, ODE/PDE의 구체적인 데모 안내를 따른다. 기존 글의 모든 수사나 강조 표시를 복제하기보다 반복되는 서술 원칙을 적용한다.

- 제목과 목차는 짧은 개념명으로 정리했다. 가제는 `에이전트와 강화학습`이며 알고리즘의 전체 목록은 도입에서 설명한다.
- 본문은 한 문단에 하나의 관계를 설명한다. `실패 로그를 받았다 → 다음 선택이 달라진다 → 그 선택을 정책이라 부른다`처럼 예제가 용어의 필요성을 만든다.
- 한국어 설명을 먼저 쓰고 첫 등장에 영문 용어를 붙인다. 이후에는 에이전트, 관측, 행동, 정책, 보상을 일관되게 사용한다. 고유 이름인 ReAct·PPO·GRPO는 그대로 쓴다.
- 수식 앞에서 변수가 가리키는 예제를 설명하고, 식 뒤에서 각 항이 하는 일을 풀어 쓴다. 식이나 알고리즘 이름을 제시하는 것만으로 설명을 끝내지 않는다.
- 도입에서 전망·혁신·자율 지능 같은 큰 주장으로 흥미를 만들지 않는다. 파일을 수정했지만 테스트가 실패하는 구체적인 상황으로 시작한다.
- `반드시 구분해야 한다`, `아주 중요하다` 같은 집필 지침은 원고에서 해당 차이를 설명하는 문장으로 바꾼다. 한계는 관련 주장 바로 뒤에서 짧게 밝힌다.
- 그림 안내에는 조작 대상과 관찰할 현상을 함께 적는다. `직관적으로 이해해보자` 대신 `수집 정책의 확률을 바꿔보세요. 같은 행동에 붙는 가중치가 달라집니다`처럼 쓴다.

### 도입 문체 견본

아래는 톤을 확인하기 위한 짧은 견본이며, 전체 본문 작성이나 구조 확정을 대신하지 않는다.

코드의 오류를 고쳐 달라고 하면 언어 모델은 수정안을 만들어 줍니다. 하지만 그 코드를 실행했을 때 테스트가 통과하는지는 별개의 문제입니다. 실패 로그를 읽고, 관련 파일을 다시 확인하고, 수정한 코드를 실행하는 과정이 이어져야 합니다. 이때 모델의 출력은 다음 행동을 정하고, 행동의 결과는 다시 모델의 입력이 됩니다.

에이전트를 이해하는 출발점은 이 반복입니다. 모델이 어떤 정보를 보고 행동을 고르는지, 도구는 그 행동을 어떻게 실행하는지, 실패한 결과가 다음 선택을 어떻게 바꾸는지부터 살펴보겠습니다. 추론과 도구 사용, 관측과 자기평가는 이 과정에서 서로 다른 역할을 맡습니다.

이 반복을 만드는 데 강화학습이 꼭 필요한 것은 아닙니다. 이미 학습된 모델에 도구와 실행 과정을 연결해도 에이전트를 만들 수 있습니다. 강화학습은 여기서 한 걸음 더 나아가, 여러 시도의 결과를 바탕으로 모델의 행동 선택을 개선합니다. 이 글에서는 그 과정을 정책과 보상의 언어로 옮긴 뒤, REINFORCE와 PPO, GRPO가 경험을 어떻게 학습 신호로 바꾸는지 따라갑니다. 교사 모델의 경험을 전달하는 distillation과 실제 학습 환경의 설계도 함께 살펴봅니다.

### 본문과 수식 설명 견본

같은 실패 로그를 받더라도 에이전트가 항상 같은 행동을 고르는 것은 아니다. 관련 파일을 더 읽을 수도 있고, 코드를 수정하거나 테스트를 다시 실행할 수도 있다. 지금까지의 기록을 \(h_t\), 다음 행동을 \(a_t\)라 하자. 각 행동을 선택할 확률을 정하는 규칙이 정책(policy)이다.

\[a_t\sim\pi_\theta(\cdot\mid h_t)\]

\(\theta\)는 모델의 파라미터다. 새 테스트 결과를 받으면 기록 \(h_t\)가 달라져 같은 모델도 다른 행동을 고를 수 있다. 강화학습에서는 여러 시도의 보상을 이용해 \(\theta\)를 바꾼다. 입력이 달라져 선택이 바뀌는 것과, 학습으로 선택 확률을 바꾸는 것이 여기서 나뉜다.

## 라운드 4 — 저자 재검토: 예시와 인용 귀속 (2026-09-08)

**예시 교체.** 초안의 running example은 이름표 함수(`" Ada " → "Ada"`, `null → "Guest"`, `0 → "0"`)였다. 세 줄짜리 함수라 다음이 담기지 않았다. ① 탐색이 필요 없다. 오류 메시지가 곧 원인이다. ② 회귀가 없다. 고쳐서 다른 것이 깨질 여지가 없다. ③ 고전 RL의 부분 관측 구조와 연결되지 않는다. 결과적으로 §Distillation의 「학생이 교사 경로에서 벗어난다」와 §설계의 「검증기 우회」가 예시의 뒷받침 없이 주장으로만 남았다.

교체한 과제는 **실패 지점과 원인이 다른 파일에 있는 버그**다. 결제 통합 테스트가 900 대신 1000을 반환하고, 트레이스는 `pricing.js`를 가리키지만 원인은 `config.js`의 `parseInt("0.1") === 0`이다. 이 하나로 다음이 모두 예시 안에서 실행된다.

- **부분 관측**: 저장소 전체를 볼 수 없어 `grep`·`read_file`로 후보를 좁혀야 한다.
- **정보 수집 행동 vs 세계를 바꾸는 행동**: `grep`은 저장소를 바꾸지 않고 `apply_patch`는 바꾼다. 고전 RL에서 센서 읽기와 이동을 구분하던 자리다.
- **회귀**: 트레이스 지점에 기본값을 채우면 대상 테스트는 통과하고 다른 테스트가 깨진다. 브라우저에서 실제로 500 기대에 450이 나온다.
- **검증 범위**: 「고정된 순서」 모드는 대상 테스트만 재실행해 통과를 보고한다. 저장소는 깨져 있다. §설계의 reward hacking·회귀 검사 논의가 그림 1에서 이미 시연된다.
- **credit assignment**: 성공한 경로 안에서 어느 `grep`이 기여했는지 outcome 보상만으로는 알 수 없다.

§에이전트에 **미로 속 로봇 ↔ 저장소 속 에이전트** 대응표를 추가해 상태·관측·행동·보상·episode를 한 줄씩 맞췄고, 이어서 무엇이 다른지(행동이 유한한 기호가 아니라 토큰열이라는 점, 정책이 백지에서 시작하지 않는다는 점)를 명시했다. 그림 1~9의 trace·rollout·트리 라벨을 모두 새 과제로 옮겼다.

**인용 귀속.** 36건의 직접인용을 감사했더니 절반 가까이가 `<cite>` 줄에만 출처가 있고 본문에는 귀속 문장이 없었다. 특히 연속된 인용의 두 번째부터는 아무런 연결 없이 인용이 이어졌고, GLM-5의 TITO 인용은 앞 문단에서 GLM-5를 언급하지도 않은 채 등장했다. Qwen3의 1/10 GPU 시간 인용은 단서가 인용보다 **앞**에 놓여 읽는 순서가 뒤집혀 있었다.

모든 인용에 「~에 따르면」 또는 「~는 …라고 적는다」 형태의 귀속 문장을 붙이고, 논문은 괄호로 저자·연도를 표기했다. 연속 인용은 「같은 abstract는」·「같은 절은」으로 이어 준다. Qwen3 항목은 귀속 → 인용 → 단서 순으로 재배열하고, 그 비교에 붙는 세 조건(특정 모델, 그 실험 조건, 좋은 교사의 존재)을 인용 뒤에 명시했다.

## 라운드 5 — MDP 정식화, 두 번째 과제, DAPO (2026-09-08)

**§에이전트에 MDP 절 신설.** 고전 RL과의 대응표만 있고 정작 “그래서 LLM의 행동을 MDP로 어떻게 적는가”가 없었다. 다섯 튜플 \((\mathcal S,\mathcal A,P,R,\gamma)\)에서 LLM 에이전트가 손대는 곳이 \(\mathcal A\)와 \(\mathcal S\) 둘뿐이라는 점을 명시하고, 다음을 추가했다.

- **행동 집합**: \(a\in\bigcup_{K\le K_{\max}}V^K\). 유한하지만 \(10^{250}\) 규모라 표로 저장할 수 없고, 토큰 단위 인수분해로만 표현된다. 이 인수분해가 보장하는 세 가지(표본추출·확률 계산·미분)가 이후 알고리즘이 요구하는 전부이며, 그래서 이 글에 Q-learning 계열이 등장하지 않는다는 점까지 연결했다.
- **같은 토큰열의 세 가지 해석**: 산출물 / 도구 호출 / 최종 응답. 행동의 종류가 다른 것이 아니라 환경이 붙이는 해석이 다르다는 표를 넣었다.
- **POMDP**: \(h_t\ne s_t\)이므로 엄밀히는 부분 관측이고, 이 글은 기록 \(h_t\)를 상태로 삼아 Markov 성질을 정의로 확보한다. 그 대가와 실무적 결과(context 관리가 바뀌면 다른 결정 문제가 된다)를 명시했다.
- **보상과 시간 축**: terminal reward, \(\gamma=1\)로 두는 이유.

**그림 1에 두 번째 과제 추가.** 저장소 디버깅만 있으면 “LLM의 행동 = 도구 호출”이라는 좁은 인상을 준다. 행동이 생성한 텍스트 그 자체인 경우를 나란히 두기 위해 **번역 과제**를 추가했다. 릴리스 노트 한 문장을 옮기되 용어집(`rate limit → 요청 제한`), 수치·날짜 보존, 존댓말 종결의 세 제약을 지켜야 한다.

두 과제는 행동의 형태가 다르지만 실패의 모양이 같도록 설계했다. 번역에서도 지적된 용어를 고치려 문장을 다시 쓰다가 통과하던 수치 검사를 깨뜨린다(5,000이 사라지고 20,000이 “2만”이 된다). 세 검사는 브라우저에서 실제로 실행되므로 이 회귀는 시나리오에 적어 둔 문자열이 아니다. 행동 옆에 「생성한 텍스트 자체가 행동 / 텍스트가 도구 호출로 해석됨」 배지를 붙여 MDP 절의 표와 그림을 직접 잇는다.

**§학습의 이유에 근거 보강.** SFT와 RL의 차이를 문장으로만 주장하고 있었다. Chu et al.(2025)의 일반화 비교를 양방향으로 인용했다. RL이 규칙 변형에 일반화하고 SFT는 암기 경향을 보인다는 문장과, 그럼에도 SFT가 출력 형식을 안정화해 뒤따르는 RL을 가능하게 한다는 문장을 함께 실었다. 이 글이 둘을 경쟁 관계로 세우지 않는 근거다. 여기에 Tulu 3 §6의 verifiable reward 정의와 DeepSeek-R1의 순수 RL 문장을 붙이고, 각각의 적용 범위(게임·내비게이션 실험, 단일 응답 추론)를 함께 적었다.

**harness 정의.** 용어표에 한 줄만 있던 것을 §LLM과 도구 사용의 본문 정의로 승격했다. 다섯 구성요소(프롬프트·도구 명세 / 파서 / 실행 환경 / context 관리 / 제어 루프와 예산)를 나열하고, MDP 절과 연결했다. harness는 환경을 정의하는 쪽이므로 도구가 \(\mathcal A\)를, context 관리가 \(h_t\)를, 예산이 episode의 끝을 정한다. 에이전트 성능을 모델 성능이라 부를 수 없는 이유가 여기서 나온다.

**DAPO를 핵심 근거로 편입.** 이 글이 “무엇을 기록할 것인가”를 말할 때 근거가 약했다. DAPO(Yu et al., 2025)를 네 자리에 넣었다.

| 절 | 인용 | 본문에서 하는 일 |
| --- | --- | --- |
| §3.2 Dynamic Sampling | 그룹의 보상이 모두 같으면 advantage가 0이고 gradient가 없다 | 그림 6에서 네 결과를 같게 만들었을 때의 현상이 실제 학습의 문제임을 확인해 준다. 「유효 그룹 비율」 지표의 근거. |
| §3.1 Clip-Higher | 학습이 진행되며 정책의 entropy가 빠르게 감소한다 | ε이 안정성만이 아니라 탐색량도 정한다는 점. entropy 기록의 근거. |
| §3.3 Token-Level Loss | 긴 응답의 토큰이 전체 loss에 불균형하게 적게 기여한다 | Dr. GRPO와 같은 진단을 다른 각도에서 보강. |
| §3.4 Overlong Reward Shaping | 잘린 샘플의 부적절한 reward shaping은 학습을 교란한다 | 그림 6의 길이 penalty가 왜 권장 설정이 아닌지. 「보상에 비용을 섞는다」를 anti-pattern에 추가. |

**이번에 잡힌 결함 둘.**

1. **모바일 가로 스크롤.** 380px에서 문서의 `scrollWidth`가 549인데 `clientWidth`가 500이었다. 보이는 요소 중에는 넘치는 것이 없어 원인이 잡히지 않다가, 요소를 하나씩 `display:none`으로 껐다 켜며 범위를 좁혀 찾았다. 원인은 KaTeX가 접근성용으로 남기는 `.katex-mathml`이다. `position:absolute`이고 1px로 클립되지만 **위치 기준이 될 조상이 없으면 초기 컨테이닝 블록을 기준으로 잡는다.** 그래서 가로로 스크롤되는 표 안쪽 깊은 위치의 수식이 표의 스크롤 박스가 아니라 문서 전체의 폭을 늘렸다. `.table-scroll`·`.formula`·`.lab`·`pre`에 `position: relative`를 주어 넘침을 스크롤 컨테이너 안에 가뒀다. 같은 구조를 쓰는 다른 글에도 있을 수 있다.
2. **번역 검사의 정규식 오류.** 존댓말 종결을 `/습니다\.$/`로 검사했는데 예시 문장은 “늘어납니다.”로 끝난다. -습니다가 아니라 -ㅂ니다여서 항상 FAIL이었다. 화면에서 통과해야 할 검사가 빨간색으로 보여 발견했다. 어간을 고정하지 않고 `/니다\.$/`로 고쳤다. 브라우저에서 실제로 실행되는 검사라 이런 오류가 눈에 보인다는 점이 이 설계의 이득이다.

**인용 형식 일괄 적용.** 인용 바로 앞 문단은 예외 없이 귀속 문장이 되도록 정리했다(44건 인용 / 44건 귀속). 새로 추가한 8건도 같은 규칙을 따른다.
# 2026-09-08 연구 튜토리얼 개정 검토

이 항목은 실제 수정과 검사 기록이다. 학회 심사나 accept 판정이 아니며, 아래에 남아 있는 가상 심사 이력과 구분한다.

- 전체 history를 Markov 상태로 다루는 것과 요약 context의 충분성을 구분했다. Harness 설명도 같은 표기를 따르도록 고쳤다.
- 토큰 공간이 크다는 이유로 Q-learning을 배제하던 단정, KL 방향으로 전체 전략 다양성을 확정하던 문장, distillation 감독량을 정보량 배율로 해석하던 문장을 정정했다.
- 실패가 언제 음의 advantage가 되는지 명시했다. 그룹 평균 baseline의 (G−1)/G 편향은 독립 표본·평균만 사용하는 조건으로 한정했다.
- 성공과 비용의 결합 자체를 anti-pattern으로 부르던 모순을 고쳤다. 원시 성분을 별도로 저장하도록 설명했다.
- DAPO clipping의 상대·절대 확률 증가를 구분했다. 그림 10의 실제 비율 정렬과 어긋나던 '환경 오류는 무조건 1순위' 설명도 고쳤다.
- 실제 grouping이 빠진 수집 의사코드에 독립 reset과 group/sample ID를 추가했다.
- 새 절: 토큰 loss 실습, 장기 credit assignment, 첫 연구의 설계. RLHF·RLVR·DPO 연결도 보강했다.
- 원형 PPO/GRPO, DAPO/Dr. GRPO, GKD, 공개 기술 보고서의 핵심 주장과 새 평가·shaping 문헌을 원 출처와 대조했다. 긴 영어 발췌 44개는 한국어 요약으로 대체했다.
- 수학 검증은 완전 열거와 직접 계산을 사용한다. 브라우저 검증은 20개 절, 기존 10개 그림, 수식 렌더링, 앵커, 중복 ID, 62개 컨트롤 설정, 1440/900/700/480/380px 화면 너비를 확인한다.

제한: 교육용 계산의 정확성과 페이지 동작을 확인한 것이며 실제 LLM의 성능을 재현한 것은 아니다. 모든 외부 문헌의 실험을 재현하거나 오류 부재를 보증하지 않는다.
# 2026-09-08 예시 단순화

사용자 요청에 따라 교육용 예시를 '정수 배열의 최댓값 찾기'로 통일했다. 결제 할인·다중 파일 탐색·번역의 예시는 현재 본문과 실행 그림에서 제거했다. 아래의 과거 예시 검토는 이력으로 남긴다.
